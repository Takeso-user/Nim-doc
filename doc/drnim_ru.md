## Введение

В этом документе описывается использование инструмента _DrNim_. DrNim сочетает
фронтенд Nim с движком доказательств [Z3](https://github.com/Z3Prover/z3),
позволяя проводить верификацию/валидацию программ, написанных на Nim.
Параметры командной строки у DrNim совпадают с параметрами компилятора Nim.

DrNim на данный момент проверяет только те участки кода, которые помечены
через `staticBoundChecks: on`:

```nim
{.push staticBoundChecks: on.}
# <--- code section here ---->
{.pop.}
```

DrNim сейчас пытается доказывать лишь проверки индексации массивов и
поддиапазонные проверки; переполнения (`overflow`) **не** предотвращаются —
обнаружение переполнений планируется в будущих версиях.

В более поздних версиях компилятора Nim будет **предполагаться**, что проверки
внутри окружения `staticBoundChecks: on` доказаны, и соответствующие
временные проверки выполнения будут **опущены**. Если вы не хотите такого
поведения, используйте вместо этого `{.push staticBoundChecks: defined(nimDrNim).}`.
Так компилятор Nim не будет знать о выполненных доказательствах, но DrNim
по-прежнему осуществит их проверку.

## Установка

Запустите `koch drnim`:cmd:, после этого исполняемый файл появится в
`$nim/bin/drnim`.

## Мотивирующий пример

Ниже пример демонстрирует, что DrNim может обнаруживать даже без дополнительных
аннотаций:

```nim
{.push staticBoundChecks: on.}

proc sum(a: openArray[int]): int =
  for i in 0..a.len:
    result += a[i]

{.pop.}

echo sum([1, 2, 3])
```

Эта программа содержит известную ошибку "index out of bounds". DrNim
обнаружит её и выведет сообщение об ошибке, например:

```
cannot prove: i <= len(a) + -1; counter example: i -> 0 a.len -> 0 [IndexCheck]
```

Иными словами, для `i == 0` и `a.len == 0` (например) случится выход за границы массива.

## Пред-, постусловия и инварианты

DrNim добавляет в Nim четыре дополнительные аннотации (pragmas):

- `requires`
- `ensures`
- `invariant`
- `assume`

Эти pragma игнорируются компилятором Nim, поэтому их не нужно отключать
через `when defined(nimDrNim)`.

### Invariant

`invariant` — это утверждение, которое должно быть истинно после каждой итерации
цикла; оно привязано к телу того цикла, в котором объявлено.

### Requires

Аннотация `requires` описывает, что процедура ожидает истинным до её вызова —
так называемое предусловие (precondition).

### Ensures

Аннотация `ensures` описывает, что будет истинно после вызова функции —
постусловие (postcondition).

### Assume

Аннотация `assume` указывает, что DrNim должен **предположить** истинным в
данном участке программы. Это небезопасный обход, сравнимый с `cast` в Nim.
Используйте `assume` только когда вы действительно уверены. Рекомендуется
сопроводить такое предположение ссылкой на внешний доказательный отчёт.

## Пример: insertionSort

**Примечание**: этот пример пока не работает с DrNim.

```nim
import std / logic

proc insertionSort(a: var openArray[int]) {.
    ensures: forall(i in 1..<a.len, a[i-1] <= a[i]).} =

  for k in 1 ..< a.len:
    {.invariant: 1 <= k and k <= a.len.}
    {.invariant: forall(j in 1..<k, i in 0..<j, a[i] <= a[j]).}
    var t = k
    while t > 0 and a[t-1] > a[t]:
      {.invariant: k < a.len.}
      {.invariant: 0 <= t and t <= k.}
      {.invariant: forall(j in 1..k, i in 0..<j, j == t or a[i] <= a[j]).}
      swap a[t], a[t-1]
      dec t
```

К сожалению, инварианты, нужные для доказательства корректности этого кода,
часто требуют большего объёма аннотированного кода, чем сами императивные
операции. Зато результат требует меньше тестирования. Заметьте, что DrNim
гарантирует только, что после `insertionSort` будет выполнено:

```
forall(i in 1..<a.len, a[i-1] <= a[i])
```

Это необходимое, но недостаточное условие для утверждения, что процедура
выполняет сортировку — например, другая процедура может установить элементы
в возрастающем порядке, не выполняя сортировку.

## Синтаксис пропозиций

Базовый синтаксис: `ensures|requires|invariant: <prop>`.
`prop` — либо сравнение, либо составное выражение:

```
prop = nim_bool_expression
     | prop 'and' prop
     | prop 'or' prop
     | prop '->' prop # implication
     | prop '<->' prop
     | 'not' prop
     | '(' prop ')' # grouping
     | forallProp
     | existsProp

forallProp = 'forall' '(' quantifierList ',' prop ')'
existsProp = 'exists' '(' quantifierList ',' prop ')'

quantifierList = quantifier (',' quantifier)*
quantifier = <new identifier> 'in' nim_iteration_expression
```

`nim_iteration_expression` — обычное Nim-выражение, описывающее пространство
итерирования, например `1..4` или `1..<a.len`.

`nim_bool_expression` — обычное Nim-выражение типа `bool`, например `a == 3`.

Поддерживаемый поднабор Nim-выражений в пропозициях пока частично
недоопределён; разрешены `let`-переменные, параметры функций и `result`.
Выражения не должны иметь побочных эффектов и должны завершаться.

Операторы `forall`, `exists`, `->`, `<->` должны быть импортированы из
`std / logic`.
