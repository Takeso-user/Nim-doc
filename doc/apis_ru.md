# Дизайн именования API

API спроектирован так, чтобы быть **простым в использовании** и последовательным. Простота оценивается количеством вызовов, необходимых для выполнения конкретной высокоуровневой операции.

## Схема именования

Библиотека использует простую схему именования с общеупотребимыми сокращениями — это делает имена короткими, но информативными. Начиная с версии 0.8.2 многие символы были переименованы в соответствии с этой схемой. Цель — чтобы разработчик мог интуитивно _угадать_ имя.

Ниже таблица с английскими терминами, рекомендуемыми сокращениями и краткими примечаниями (примечания переведены на русский).

| English word      | To use      | Notes (рус.)                                                                                                     |
| ----------------- | ----------- | ---------------------------------------------------------------------------------------------------------------- |
| initialize        | initT       | `init` используется для создания value type `T`                                                                  |
| new               | newP        | `new` используется для создания reference type `P`                                                               |
| find              | find        | должен возвращать позицию, где что-то найдено; для булева результата используйте `contains`                      |
| contains          | contains    | часто сокращение для `find() >= 0`                                                                               |
| append            | add         | предпочтительнее `add` вместо `append`                                                                           |
| compare           | cmp         | должен возвращать int с семантикой `< 0`, `== 0`, `> 0`; для булева результата используйте `sameXYZ`             |
| put               | put, `[]=`  | стоит рассмотреть перегрузку `[]=` для операций put                                                              |
| get               | get, `[]`   | стоит рассмотреть перегрузку `[]` для get; можно не использовать префикс `get` — например, `len` вместо `getLen` |
| length            | len         | также используется для обозначения количества элементов                                                          |
| size              | size, len   | `size` должен относиться к размеру в байтах                                                                      |
| capacity          | cap         |                                                                                                                  |
| memory            | mem         | подразумевает низкоуровневую операцию                                                                            |
| items             | items       | итератор по элементам коллекции (по умолчанию)                                                                   |
| pairs             | pairs       | итератор по (key, value) парам                                                                                   |
| delete            | delete, del | `del` предполагается быстрее, так как не сохраняет порядок; `delete` сохраняет порядок                           |
| remove            | delete, del | сейчас неконсистентно                                                                                            |
| remove-and-return | pop         | `Table`/`TableRef` — алиас для `take`                                                                            |
