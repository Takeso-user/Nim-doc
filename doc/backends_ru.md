# Интеграция бэкендов Nim

## Введение

Nim обычно компилирует `.nim` файлы в один или несколько `.c` файлов (команда `compile`/`c`), которые далее собираются с помощью системного C-компилятора в исполняемый файл. Кроме этого, доступны генерация кода для C++, Objective-C и JavaScript. Этот документ собирает опции интеграции и бэкендов в одном месте.

Компилятор Nim поддерживает две основные семьи бэкендов: C-подобные (C, C++, Objective-C) и JavaScript. C-подобные таргеты генерируют код, который можно собрать в библиотеку или исполняемый файл; JavaScript-таргет генерирует `.js` файл для использования в браузере или Node.js.

Кроме генерации кода, Nim предоставляет двунаправленный интерфейс с бэкендами через общие и специфичные pragma'ы.

## Backends

### C-like targets

Команды для генерации кода:

- `//compileToC`, `cc` — compile project with C code generator
- `//compileToCpp`, `cpp` — compile project to C++ code
- `//compileToOC`, `objc` — compile project to Objective C code

В каталоге `nimcache` будут файлы с расширениями `.c`, `.cpp` или `.m` в зависимости от выбранного таргета. В остальном команды производят нативный бинарник для проекта и позволяют встраивать сгенерированный код в проекты на соответствующем языке.

Примеры команд:

```cmd
nim c hallo.nim
nim cpp hallo.nim
nim objc hallo.nim
```

При необходимости можно указать дополнительные опции для кросс-компиляции (target CPU, OS, компилятор/линкер).

### JavaScript target

Nim может генерировать JavaScript через команду `js`.

Nim таргетирует JavaScript 1.5, совместимый с большинством браузеров. Из-за ограничений импорта модулей Nim генерирует один большой `.js` файл.

Неподдерживаемые в JavaScript возможности/модули включают:

- ручное управление памятью (`alloc` и т.д.)
- небезопасные операции (`cast`, `zeroMem` и т.д.)
- работу с файлами
- OS-специфичные операции
- потоки, корутины
- некоторые модули стандартной библиотеки

Стандартная библиотека содержит модули, адаптированные для JS-таргета, и поддержка будет расширяться (например, Node.js биндинги).

Для запуска в Node.js можно использовать `nim js -r examples/hallo.nim`.

Если возникают ошибки, связанные с `globalThis` в Node.js, используйте Node.js версии >= 12.0.

## Interfacing

Nim предоставляет двунаправленный интерфейс с бэкендом: из Nim можно вызывать бэкенд-функции и наоборот. Обычно направление зависит от архитектуры приложения (Nim — главная программа или компонент).

### Nim code calling the backend

Для вызова бэкенд-кода из Nim используется FFI и `importc` pragma (универсально для всех таргетов, включая JS). Для C++ и Objective-C есть `ImportCpp` и `ImportObjC` pragma'ы.

Для C-подобных таргетов нужно линковать нативный код статически или динамически. Предпочтительна динамическая линковка, чтобы не требовать наличия development-библиотек при компиляции. Для этого используется pragma `dynlib` или модуль `dynlib`.

Можно использовать `dynlibOverride` для принудительной статической линковки; `compile` pragma помогает встраивать исходники в Nim проект; `PassL` pragma позволяет передать линкеру конкретные библиотеки.

Инструмент `c2nim` помогает генерировать интерфейсы из C-заголовков.

#### Пример вызова C из Nim

Файл `logic.c`:

```c
int addTwoIntegers(int a, int b)
{
  return a + b;
}
```

Файл `calculator.nim`:

```nim
{.compile: "logic.c".}
proc addTwoIntegers(a, b: cint): cint {.importc.}

when isMainModule:
  echo addTwoIntegers(3, 7)
```

Компиляция и запуск:

```cmd
nim c -r calculator.nim
```

Или собрать статическую библиотеку и передать её через `--passL`.

#### Пример вызова JavaScript из Nim

`host.html`:

```
<html><body>
<script type="text/javascript">
function addTwoIntegers(a, b)
{
  return a + b;
}
</script>
<script type="text/javascript" src="calculator.js"></script>
</body></html>
```

`calculator.nim`:

```nim
proc addTwoIntegers(a, b: int): int {.importc.}

when isMainModule:
  echo addTwoIntegers(3, 7)
```

Сборка в JS:

```cmd
nim js -o:calculator.js calculator.nim
```

Откройте `host.html` в браузере и посмотрите консоль — должно вывести `10`.

### Backend code calling Nim

Для вызова Nim из бэкенда используется `exportc` pragma — он позволяет сохранить имя символа или задать альтернативное имя для бэкенда.

C-требует инициализации внутренних структур Nim с помощью вызова `NimMain()`. Имя функции можно изменить с помощью опции `--nimMainPrefix:prefix`.

При компиляции в библиотеки глобальные деструкторы не вызываются автоматически; предоставлена функция `NimDestroyGlobals` (также влияет `--nimMainPrefix`).

#### Пример вызова Nim из C

`fib.nim`:

```nim
proc fib(a: cint): cint {.exportc.} =
  if a <= 2:
    result = 1
  else:
    result = fib(a - 1) + fib(a - 2)
```

`maths.c`:

```c
#include <stdio.h>

int fib(int a);
void NimMain();

int main(void)
{
  NimMain();
  for (int f = 0; f < 10; f++)
    printf("Fib of %d is %d\n", f, fib(f));
  return 0;
}
```

Генерация и сборка (пример для Unix-подобной системы):

```cmd
nim c --noMain --noLinking fib.nim
gcc -o m -I$HOME/.cache/nim/fib_d -Ipath/to/nim/lib $HOME/.cache/nim/fib_d/*.c maths.c
```

Можно также попросить компилятор сгенерировать статическую библиотеку:

```cmd
nim c --app:staticLib fib.nim
gcc -o m -Inimcache -Ipath/to/nim/lib maths.c libfib.nim.a
```

> Заметьте: команды могут отличаться в зависимости от системы (на Linux, возможно, понадобится `-ldl`).

## Nimcache naming logic

Каталог `nimcache` генерируется при компиляции и содержит временные или итоговые файлы в зависимости от таргета. Имя каталога по умолчанию зависит от таргета и ОС; его можно изменить с помощью `--nimcache`.

## Memory management

Для JS проблем с управлением памятью нет — GC у JS берёт на себя очистку. Для C-подобных бэкендов необходимо уделять внимание владению памятью при обмене объектами между Nim и C.

### Strings and C strings

Nim strings неявно преобразуются в `cstring`, так что большинство C-функций могут работать с ними без дополнительной заботы. Однако если C-код сохраняет указатель на строку, нужно учесть время жизни буфера.

Пример:

```nim
proc gimme(): cstring {.exportc.} =
  result = "Hey there C code! " & $rand(100)
```

После выхода из `gimme` Nim может освободить память `cstring`, если C не хранит на неё ссылку и не увеличивает счётчик.

### Custom data types

Пользовательские структуры, передаваемые между Nim и бэкендом, требуют явного управления временем жизни. Для передачи Nim-ссылки в C используйте `GC_ref` чтобы предотвратить её сбор, а для освобождения — `GC_unref`.

Если библиотека на C использует `malloc`/`free`, оберните соответствующие функции и аккуратно управляйте освобождением памяти с обеих сторон.
